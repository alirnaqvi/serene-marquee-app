# Serene Marquee — September 2026 changes

Everything below is already applied in this zip. Run
`supabase/migration-2026-09.sql` (after `migration-2026-08.sql`) before
deploying.

---

## 1. Loans now appear on payroll and in the export

Payroll has a new **Loan / Advance Balance** column sitting right after Net
Payable, showing each employee's total outstanding split into loan vs advance,
plus the agreed monthly cut. Employees with nothing owing read "Clear". A sixth
summary card at the top shows total **Loans Outstanding** across all staff.

The Excel export is now a **two-sheet workbook**:

- **Sheet 1 — the month.** Adds `Loan Instalment` (what was actually deducted
  this month), `Loan Balance`, `Advance Balance` and `Total Outstanding`
  columns, plus a bold totals row.
- **Sheet 2 — Advances & Loans.** Every advance and loan ever issued, with the
  amount, monthly deduction, how much has been recovered, what's still
  outstanding, and whether it's Open or Cleared.

## 2. Balance shown against each employee

Covered by the same Loan / Advance Balance column above. It recalculates the
moment you apply an instalment or record a new advance, since the balance is
derived from the transactions rather than stored separately — it can't drift
out of sync.

## 3. Menu is per head throughout

Every add-on is now charged per head. Quantity always follows the guaranteed
guest count, the per-unit number input is gone, and both the Menus screen and
the Customized Menu picker read "/ head" for every item.

A few items (cold drinks, lamb roast, mutton leg, the stalls) had been entered
with the wrong quantity mode and were being multiplied per unit. **No prices
change** — every item keeps its current rate, and only the mode is corrected.

## 4. New discount limits

| Role | Limit per booking |
|---|---|
| Manager (Zain Syed) | Rs. 50,000 |
| General Manager (Ikram Abbasi) | Rs. 100,000 |
| Staff / Owner | none |
| Admin / Developer | unlimited |

Enforced in the booking form and by the database trigger, and the Staff & Access
policy card is updated to match.

## 5. Ledger shows newest first

The table and the export both list the most recent entry at the top. The running
balance is still computed in true date order behind the scenes, so the figures
are unchanged — only the display order flipped. The "Balance Carried" card now
reads from the newest row.

## 6. Booking summaries by date range or month

The bookings screen has **Date From** and **Date To** pickers (set both to the
same day for a single date), a **Quick Month** dropdown, a **This Month**
button, and a status filter.

A summary panel sits above the table and reflects whatever is currently
filtered: bookings count split by status, cancelled count with refunded total,
guests, gross total, discount given, advance received, and balance due.
Cancelled bookings are excluded from the money figures.

**⤓ Download Excel** exports exactly what's on screen, with a title block
naming the period and a totals row.

## 7. Vendor account diary

Vendors now works like the shop diary the office already keeps, with multiple
entries per day fully supported.

Click any vendor row to open its account, which shows every entry as
**Date · Description · Debit · Credit · Balance**, with a running balance and a
totals row. Toggle between full history and a single month, and hit **Download
Excel** for the same table as a spreadsheet.

- **Credit** = a bill received from the shop → increases what we owe
- **Debit** = a payment made → reduces what we owe, and posts to the daily
  ledger as an expense (checkbox, on by default)
- **Balance** = what's still payable

The vendor list gained Entries / Billed / Paid / Balance columns for the
selected month, and the summary cards now show Billed, Paid and total Balance
Payable. **⤓ Excel (all)** produces a workbook with a summary sheet plus one
sheet per vendor.

Your existing vendor payments were recorded through the ledger; the migration
backfills them into the diary as debit entries, so no history is lost.

## 8. CSV removed — xlsx only

Every CSV button is gone. All exports are now genuine `.xlsx` workbooks with
real numeric cells, so totals, sorting and filtering work in Excel — the old
export was a renamed HTML table that Excel merely tolerated.

This is generated by a small in-house writer (`src/lib/xlsx.ts`) on top of
`fflate`, the one new dependency at ~8KB. Files come out with a bold title
block, a shaded frozen header row, autofilter, thousands separators, sized
columns and a bold totals row.

# Round 15 — drafts, discount history, editable rates

Run `supabase/migration-2026-15.sql` in the Supabase SQL editor before
deploying. It is safe to re-run.

## 1. Fixed: an approved discount could not be saved

Approving Rs. 116,250 on SM-000004 told the requester "you can save this
booking", and then saving it refused with *"Rs. 116250 is above your own limit
of Rs. 100000. Pass this request up to the Admin instead."*

The permit is spent by a database trigger that updates the approval row when
the booking is saved. A second trigger re-checked that row against **the
current user's** discount ceiling — correct while an approver is deciding, but
that update runs as the *requester*, so a Manager spending a Rs. 116,250
permit was checked against the Manager's own Rs. 100,000 limit.

The check now only runs when a request is actually being decided, or when the
granted figure is changed. Spending, dismissing and every other later touch of
the row pass straight through.

**Also fixed:** *Dismiss* on the approval notice did nothing. It ran a delete,
and the delete rule only permits pending requests, so the card came straight
back. It now marks the notice as seen and keeps the request.

## 2. "Open booking" on the approval notice

The approved/declined notice on the dashboard now carries an **Open booking**
button next to Dismiss, going straight to the booking the discount was granted
against. Requests raised before the booking existed reopen the new-booking form
with the date filled in.

## 3. Draft bookings

A booking form that is started but not finished is no longer lost. It saves
itself as a **draft** a couple of seconds after typing stops, and there is a
**Save as Draft** button for parking it deliberately.

A draft is not a booking:

- it does not appear on the calendar and does not hold the date
- it is not counted as a clash, so the venue stays free
- it counts towards no total anywhere — bookings, guests, gross, balance
- only the person who started it can see it (plus Admin and Developer)

Drafts are listed in Bookings with a **Resume** button and a *Draft
(unfinished)* filter. Resuming opens the form where it was left; **Save
Booking** turns that same record into a Tentative or Confirmed booking, so no
duplicate is left behind.

## 4. Discount request history

Every request is kept permanently — pending, approved or declined — and the
dashboard has a **Discount Requests** card showing the split. Clicking it opens
the full history, which shows what each role needs:

| Role | Sees |
|---|---|
| Manager | every request they made, and what was decided |
| General Manager | requests that came to them, plus their own to the Admin |
| Admin | every request that reached them |

Each row expands to the booking it was raised against — client, date, sitting,
venue, function, guests, menu, booking total, the discount at the time, the
requester's own limit, who decided it and when, and whether the approval has
actually been used. Searchable by order number, client, requester or reason.

## 5. Search on Ledger, Payroll and Vendors

The same kind of search box the bookings screen has:

- **Ledger** — description, who the money was handed to, category, who recorded
  it, the date, or an amount
- **Payroll** — name, designation, phone, salary
- **Vendors** — what they supply, shop name, notes, contact number

## 6. Menus & Venues is now editable by the Admin

The rate card stopped being fixed in the code. On Menus & Venues the Admin can
now:

- add, rename and delete **menus**, and edit the item list of each one
- add and delete **venues** and change capacity, hall charge, the guest count
  above which the hall charge is waived, and the decoration starting price
- add, rename and delete **add-on items**
- change every **owner charge rule**: KPRA tax %, cooling per hall, heating per
  heater, the confirmation token, the extra-hour charge, the advance needed to
  confirm a booking, and the entry-test rate

Change KPRA from 15% to 13% and every **new** booking form, quotation,
agreement and ledger entry uses 13% from that moment on. Bookings already saved
keep the figures they were agreed at — a rate change must never quietly rewrite
a signed agreement.

Everyone else sees the same page, read-only.
